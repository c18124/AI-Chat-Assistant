## 5. `index.html` 代码改造说明

## 5.1 HTML 文档基础设置

文件开头增加了：

```html
<html lang="zh-CN">
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
<meta name="theme-color" content="#04182d">
```

作用分别是：

- `lang="zh-CN"`：告诉浏览器和辅助工具页面主要语言是中文。
- `charset="UTF-8"`：保证中文不会乱码。
- `viewport`：让页面在手机上按照真实屏幕宽度显示，而不是缩小后的桌面页面。
- `viewport-fit=cover`：允许页面合理利用带刘海或安全区域的移动设备屏幕。
- `theme-color`：部分手机浏览器会使用该颜色装饰浏览器顶部区域。

还加入了内嵌 SVG favicon，避免浏览器自动请求不存在的 `favicon.ico` 产生 404 控制台错误。

## 5.2 外部样式与脚本

页面加载以下资源：

```html
<link rel="stylesheet" href="./static/css/style.css">

<script src="https://cdn.jsdelivr.net/npm/marked/marked.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/dompurify@3.4.17/dist/purify.min.js"></script>
<script src="https://cdnjs.cloudflare.com/ajax/libs/highlight.js/11.9.0/highlight.min.js"></script>
<script src="https://cdnjs.cloudflare.com/ajax/libs/gsap/3.12.5/gsap.min.js"></script>
<script src="./static/js/animation.js"></script>
```

各自用途：

- `style.css`：页面全部视觉样式。
- `marked`：把 Markdown 文本转换为 HTML。
- `DOMPurify`：清理 Markdown 生成的 HTML，降低 XSS 风险。
- `highlight.js`：给代码块添加语法高亮。
- `GSAP`：执行页面入场和消息动画。
- `animation.js`：调用 GSAP 并管理视频加载状态。

## 5.3 海洋视频背景

核心 HTML：

```html
<video
    id="ocean-video"
    class="ocean-video"
    autoplay
    muted
    loop
    playsinline
    preload="metadata"
    poster="./images/background.png"
>
    <source src="./static/videos/ocean.mp4" type="video/mp4">
</video>
```

属性说明：

- `autoplay`：打开页面后自动播放。
- `muted`：视频静音。现代浏览器通常只允许静音视频自动播放。
- `loop`：视频结束后自动重新播放。
- `playsinline`：手机端在网页内部播放，不强制进入全屏播放器。
- `preload="metadata"`：先加载视频尺寸、时长等基础信息。
- `poster`：视频尚未就绪时显示备用图。

视频位于独立背景层中，发送消息、切换模式和更新聊天 DOM 时都不会重新创建视频元素，因此不会因为聊天操作而重新加载。

## 6. `style.css` 视觉系统说明

## 6.1 CSS 变量

文件顶部 `:root` 定义了统一变量：

```css
:root {
    --nav-height: 76px;
    --page-gutter: clamp(16px, 3vw, 48px);
    --glass-strong: rgba(5, 25, 48, 0.72);
    --text-main: #f4fbff;
    --cyan: #79dcff;
    --shadow-xl: 0 34px 90px rgba(0, 10, 27, 0.44);
}
```

CSS 变量的好处：

- 颜色、间距、阴影集中管理。
- 修改主题时不需要逐行寻找颜色值。
- 保持导航、按钮和聊天卡片风格一致。

## 6.2 `box-sizing: border-box`

```css
* {
    box-sizing: border-box;
}
```

默认盒模型中，元素实际宽度可能是：

```text
内容宽度 + padding + border
```

使用 `border-box` 后，设置的宽度已经包含内边距和边框，更容易控制响应式布局。

## 6.3 背景分层与 `position`

背景容器：

```css
.ocean-background {
    position: fixed;
    inset: 0;
    z-index: 0;
}
```

解释：

- `position: fixed`：背景固定在浏览器视口，不跟随聊天区域滚动。
- `inset: 0`：等价于 `top/right/bottom/left` 全部为 `0`。
- `z-index: 0`：背景位于内容层下方。

内部视频和遮罩使用 `position: absolute`：

```css
.ocean-video,
.background-overlay {
    position: absolute;
    inset: 0;
}
```

父元素提供定位范围，子元素可以完全覆盖父元素。

## 6.4 `object-fit: cover`

```css
.ocean-video {
    width: 100%;
    height: 100%;
    object-fit: cover;
}
```

它会：

- 保持视频原始比例。
- 让视频铺满整个浏览器。
- 必要时裁掉一部分边缘。
- 不会把海浪横向或纵向拉伸变形。

## 6.5 视频加载状态

视频默认透明：

```css
.ocean-video {
    opacity: 0;
}
```

加载成功后，JavaScript 给背景加上 `video-ready`：

```css
.ocean-background.video-ready .ocean-video {
    opacity: 1;
}
```

加载失败时加入 `video-error`，视频被隐藏，备用背景继续显示。

这是一种常见的“状态类名控制样式”写法。

## 6.6 `z-index` 层级

当前主要层级可以理解为：

```text
z-index 10  顶部导航栏
z-index 5   工作台和聊天卡片
z-index 4   环境光晕
z-index 3   背景纹理
z-index 2   深蓝遮罩
z-index 1   海洋视频
z-index 0   备用背景
```

只有设置了定位属性的元素，`z-index` 才更容易按照预期工作。

## 6.7 深蓝渐变遮罩

遮罩不是简单的纯黑透明层，而是多层渐变：

```css
.background-overlay {
    background:
        linear-gradient(180deg, rgba(...), rgba(...)),
        linear-gradient(90deg, rgba(...), transparent, rgba(...));
}
```

作用：

- 保留海洋视频细节。
- 压低过亮区域。
- 提高白色文字和玻璃卡片的对比度。
- 让画面具有从顶部到下方逐渐变深的电影感。

## 6.8 毛玻璃效果

聊天主卡片：

```css
.chat-panel {
    background: rgba(...);
    border: 1px solid rgba(...);
    box-shadow: ...;
    backdrop-filter: blur(24px) saturate(135%);
    -webkit-backdrop-filter: blur(24px) saturate(135%);
}
```

几个属性共同完成毛玻璃：

- 半透明 `background`：让背景可以透出来。
- `backdrop-filter: blur()`：模糊元素后方的海景。
- `saturate()`：适当增强后方颜色。
- 半透明边框：模拟玻璃边缘。
- 内外阴影：增加悬浮层次。

`backdrop-filter` 模糊的是元素后方内容，不是聊天文字本身。

## 6.9 Grid 与 Flex 的分工

页面主区域使用 Grid：

```css
.workspace {
    display: grid;
    grid-template-rows: auto minmax(0, 1fr);
}
```

含义：

- 第一行标题根据内容自动决定高度。
- 第二行聊天卡片占据剩余空间。
- `minmax(0, 1fr)` 允许聊天卡片缩小，并让内部滚动正常工作。

导航、品牌、状态和模式选择多使用 Flex：

```css
display: flex;
align-items: center;
justify-content: space-between;
```

Flex 更适合一维横向排列，Grid 更适合页面区域和行列布局。

## 6.10 独立滚动消息区

```css
#chat {
    min-height: 0;
    overflow-y: auto;
    overscroll-behavior: contain;
}
```

作用：

- 消息很多时只滚动消息区。
- 导航栏和输入框保持稳定。
- `overscroll-behavior: contain` 减少滚动继续传递给外层页面。

## 6.11 用户与 AI 消息气泡

用户消息：

```css
.message.user {
    margin-left: auto;
    border-bottom-right-radius: 6px;
    background: linear-gradient(...);
}
```

AI 消息：

```css
.message.ai {
    margin-right: auto;
    border-bottom-left-radius: 6px;
    background: linear-gradient(...);
}
```

`margin-left: auto` 把用户气泡推到右侧；`margin-right: auto` 让 AI 气泡保持在左侧。

## 6.12 Markdown 与代码块

代码块设置：

```css
.message pre {
    max-width: 100%;
    overflow-x: auto;
}

.message pre code {
    min-width: max-content;
}
```

长代码不会把聊天卡片撑宽，而是在代码块内部横向滚动。

## 6.13 输入框发光

```css
#input-area:focus-within {
    border-color: rgba(...);
    box-shadow: 0 0 0 4px rgba(...);
}
```

`focus-within` 表示：只要容器内部任意输入元素获得焦点，容器就使用该样式。

因此用户点击输入框时，整个输入区域都会出现柔和光效。

## 6.14 发送按钮动效

发送按钮使用三种动画：

1. `transition`：处理悬停时的位移、阴影和亮度。
2. `::before`：创建从按钮表面划过的高光。
3. `transform`：点击时轻微缩小，形成按压反馈。

按钮禁用时：

```css
#send:disabled {
    cursor: wait;
    opacity: 0.68;
    transform: none;
}
```

这样生成回答期间不会重复触发发送。

## 6.15 CSS Keyframes

项目使用的关键帧包括：

- `statusPulse`：工作台忙碌状态灯。
- `thinkingPulse`：AI 思考圆点。
- `dotWave`：三个加载点依次跳动。
- `toastIn`：提示框淡入。

CSS Keyframes 适合循环或简单状态动画；GSAP 更适合多个元素按顺序进入。

## 6.16 响应式布局

项目设置了几个主要断点：

```css
@media (max-width: 900px) { ... }
@media (max-width: 640px) { ... }
@media (max-height: 760px) and (min-width: 641px) { ... }
```

它们分别处理：

- 平板与较窄笔记本。
- 手机竖屏。
- 高度较低的笔记本屏幕。

手机端主要变化：

- 减小页面边距。
- 隐藏较次要的品牌副标题和状态文字。
- 清空按钮只显示图标。
- 发送按钮只显示图标。
- 聊天气泡最大宽度提高到 `91%`。
- 输入区和聊天卡片圆角缩小。

## 6.17 `vh` 与 `dvh`

```css
height: calc(100vh - var(--nav-height));
height: calc(100dvh - var(--nav-height));
```

- `vh` 是传统视口高度单位。
- `dvh` 是动态视口高度，会根据手机浏览器地址栏和工具栏变化进行调整。

先写 `vh` 再写 `dvh`，旧浏览器可以使用前者，新浏览器使用后者。

## 6.18 减少动画设置

```css
@media (prefers-reduced-motion: reduce) {
    * {
        animation-duration: 0.01ms !important;
        transition-duration: 0.01ms !important;
    }
}
```

如果用户在操作系统中开启“减少动画”，页面就会取消大部分动画，提升可访问性。

## 7. `animation.js` 代码说明

## 7.1 IIFE 独立作用域

脚本外层：

```javascript
(function () {
    "use strict";
    // 动画代码
})();
```

这是立即执行函数表达式，简称 IIFE。

作用：

- 创建独立变量作用域。
- 避免与 `index.html` 中的变量重名。
- 页面加载脚本时立即进行初始化。

## 7.2 检查减少动画偏好

```javascript
const reduceMotion = window.matchMedia(
    "(prefers-reduced-motion: reduce)"
).matches;
```

如果结果为 `true`，GSAP 动画函数会直接返回，不影响页面内容显示。

## 7.3 检查 GSAP 是否存在

```javascript
function hasGsap() {
    return typeof window.gsap !== "undefined";
}
```

如果 CDN 加载失败，`window.gsap` 不存在。脚本不会继续调用 GSAP，因此聊天页面仍可正常使用。

## 7.4 页面入场动画 `playEntrance()`

执行顺序：

```text
顶部导航栏淡入
    ↓
英文辅助标题、主标题、说明依次出现
    ↓
聊天卡片从下方向上浮现
```

GSAP `timeline` 用来组织顺序：

```javascript
const timeline = window.gsap.timeline({
    defaults: {
        duration: 0.72,
        ease: "power3.out"
    }
});
```

- `duration`：动画时长。
- `ease`：速度曲线。
- `stagger`：多个元素之间错开出现。
- `"-=0.28"`：让下一段动画提前 0.28 秒开始，形成自然衔接。

## 7.5 新消息动画 `animateMessage()`

函数接收刚创建的消息 DOM：

```javascript
function animateMessage(messageElement) { ... }
```

它会判断消息角色：

- 用户消息从右侧轻微进入。
- AI 消息从左侧轻微进入。

动画只播放一次，不会让已经显示的聊天内容持续晃动。

## 7.6 清空动画 `animateClear()`

清空成功后，聊天区重新显示空状态。

该函数只让空状态轻微向上淡入，不使用夸张缩放。

## 7.7 视频状态 `setupBackgroundVideo()`

它监听：

```javascript
video.addEventListener("canplay", markReady, { once: true });
video.addEventListener("error", markError, { once: true });
```

- `canplay`：浏览器已经有足够数据开始播放。
- `error`：视频资源加载或解码失败。
- `{ once: true }`：事件处理只执行一次，避免重复触发。

加载成功时给背景添加 `video-ready`；失败时添加 `video-error`。

## 7.8 暴露有限接口

```javascript
window.oceanUI = {
    animateMessage,
    animateClear
};
```

`index.html` 只需要调用两个动画函数，因此只暴露这两个函数，不把全部内部变量放到全局作用域。

## 8.8 自动滚动 `scrollChatToBottom()`

## 8.9 Markdown 安全渲染 `renderMarkdown()`

必须注意：`marked.parse()` 只负责转换格式，不负责安全过滤。因此不能省略 `DOMPurify.sanitize()`。

## 8.13 发送消息 `sendMessage()`

这是前端最重要的函数。

第一阶段：读取和检查输入。

```javascript
const question = questionInput.value.trim();

if (!question || sendButton.disabled) {
    return;
}
```

- `trim()` 去除首尾空格。
- 空消息不发送。
- 按钮已经禁用时不重复发送。

第二阶段：选择接口。

```javascript
const useRag = chatMode.value === "rag";
const endpoint = useRag
    ? `${API_BASE}/rag/chat`
    : `${API_BASE}/chat/stream`;
```

第三阶段：构造 JSON。

```javascript
const requestData = {
    user_id: USER_ID,
    question
};
```

第四阶段：更新界面。

```text
setBusy(true)
  ↓
显示用户消息
  ↓
清空输入框
  ↓
显示 AI 加载气泡
```

第五阶段：发送 Fetch 请求。

```javascript
const response = await fetch(endpoint, {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify(requestData)
});
```

这里：

- `method: "POST"` 表示提交数据。
- `Content-Type` 告诉 FastAPI 请求体是 JSON。
- `JSON.stringify()` 把 JavaScript 对象转换为 JSON 字符串。
- `await` 等待异步网络操作完成，但不会冻结整个浏览器界面。

## 8.14 RAG 响应分支

RAG 接口返回普通 JSON：

```javascript
const result = await response.json();
answer = result.answer || "";
renderMarkdown(loading.contentElement, answer);
```

这一分支不会假装使用流式协议，保持了后端真实实现方式。

## 8.15 普通聊天流式分支

普通聊天接口返回文本流：

```javascript
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
```

读取循环：

```javascript
while (true) {
    const { done, value } = await reader.read();

    if (done) {
        break;
    }

    const text = decoder.decode(value, { stream: true });
    answer += text;
    renderMarkdown(loading.contentElement, answer);
}
```

变量说明：

- `reader`：读取响应数据流。
- `done`：数据流是否结束。
- `value`：本次收到的二进制数据块。
- `TextDecoder`：把二进制转换为 UTF-8 文本。
- `answer`：累计保存已经收到的所有文本。

为什么每次都用完整 `answer` 重新渲染？

因为 Markdown 标记可能被拆到多个数据块中。例如第一块只有三个反引号的一部分，只有累计后才能正确解析完整代码块。

## 8.16 错误处理

如果尚未收到任何回答：

- 删除加载气泡。
- 添加“服务器暂时无法完成请求”的 AI 消息。

如果已经收到部分回答后中断：

- 保留已经生成的内容。
- 在气泡底部追加“回答生成中断”。

中断文字使用：

```javascript
interruption.textContent = "⚠ 回答生成中断，请稍后重试。";
```

不使用 `innerHTML +=`，避免破坏已有 DOM 和增加 HTML 注入风险。

## 8.17 `finally` 恢复交互

无论请求成功还是失败，都会执行：

```javascript
setBusy(false);
questionInput.focus();
```

因此输入框和按钮不会永久停留在禁用状态。

## 11. 安全设计要点

## 11.1 前端不保存 API Key

DeepSeek API Key 仍然只由 Python 后端读取。前端只调用本地 FastAPI，不接触密钥。

## 11.2 Markdown 必须清理

正确顺序：

```javascript
DOMPurify.sanitize(marked.parse(content))
```

不能只写：

```javascript
marked.parse(content)
```

原因是 Markdown 中可能混入危险 HTML。

## 11.3 用户可变文本优先使用 `textContent`

Toast、时间戳、错误说明等纯文本使用 `textContent`，不会被浏览器当作 HTML 解析。

## 11.4 数据库没有被前端视觉升级覆盖

本次没有删除或重建 `chat.db`，也没有修改数据库表结构。

## 18. 适合初学者的核心术语

### HTML

描述页面结构，例如标题、按钮、输入框和聊天区域。

### CSS

控制页面外观与布局，例如颜色、尺寸、毛玻璃和响应式。

### JavaScript

控制页面行为，例如发送请求、创建消息和处理按钮点击。

### DOM

浏览器把 HTML 转换成的对象树。JavaScript 通过 DOM 查找、创建、修改和删除页面元素。

### `position: relative`

元素仍然保留在正常布局中，同时可以成为绝对定位子元素的参考范围。

### `position: absolute`

元素脱离正常文档流，根据最近的定位祖先进行定位。

### `position: fixed`

元素固定在浏览器视口中。背景视频使用它铺满屏幕。

### `z-index`

控制定位元素的前后层级。

### `object-fit: cover`

保持图片或视频比例铺满容器，必要时裁切边缘。

### `backdrop-filter`

处理元素后方的画面，常用于毛玻璃。

### `transition`

元素属性从一个状态平滑过渡到另一个状态，例如按钮悬停。

### `@keyframes`

定义一组动画阶段，适合加载点和状态灯等循环动画。

### GSAP

JavaScript 动画库，适合控制多个元素的顺序和时间线。

### `async / await`

以接近同步代码的写法处理异步操作，例如网络请求。

### Fetch

浏览器提供的网络请求 API，用来调用 FastAPI。

### JSON

前后端交换结构化数据的常用文本格式。

### 流式响应

服务器不是等完整回答生成后一次返回，而是生成一点就发送一点。

### Markdown

使用简单符号表示标题、列表、粗体和代码块的文本格式。

### XSS

攻击者把恶意 HTML 或脚本混入页面内容并执行。DOMPurify 用来降低该风险。

## 21. 本次改造总结

本次升级的核心不是单纯“换皮肤”，而是在保护原有聊天业务的前提下，把页面分成清晰的视觉层和功能层：

- HTML 负责结构。
- CSS 负责视频、玻璃、布局和响应式。
- `animation.js` 负责非关键动画。
- `index.html` 中的聊天脚本负责真实业务交互。
- FastAPI 继续负责接口。
- DeepSeek 和 RAG 继续负责回答。
- SQLite 继续负责历史记录。

即使 GSAP 加载失败，聊天功能仍然可以工作；即使背景视频失败，备用背景仍然可以显示；即使网络请求失败，输入框和按钮也会恢复。这就是本次代码中最重要的工程思想：视觉增强不能破坏核心功能。
